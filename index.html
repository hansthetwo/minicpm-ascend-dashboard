优先落地组合

避免再次投入低收益微优化
  1. P1：condition device fusion，把 COND-2~5 作为一个包做，目标净省5–14 ms/run。
  2. P1：LLM hidden fragment批量D2H，目标净省4–12 ms/run。
  3. P1：输入预处理双缓冲，先补IN-2~5分项计时；阶段收益大但官方指标折扣高。
  4. P1：异步有序WAV writer，只有PCM+write P95≥1 ms才实现。
  5. P2：head/sampler，只接受同轨迹、3W20完整链路改善≥1%的方案。

先对准正式指标

稳态 RTF 与 SPEAK→wav 不是同一个优化目标；同一改动可能只改善其中之一
Tframe = max(TVPM, TAPM) + Tprefill + Tdecode + TTTS + TToken2Wav
Encoder 只优化临界侧

VPM/APM 已并行；只有降低两者较慢一侧才会减少该帧 RTF。当前样本 VPM 墙钟显著高于 APM，应先拆分 CPU/NPU 后验证。

Overlap 主要看首包延迟

流水重叠可减少等待和 SPEAK→wav，但若两个 NPU stage 自身变慢，正式 pooled RTF 可能不降反升。

建议优化方案

优先攻击每 token / 每窗口重复发生的同步、分配和搬运；优先级已结合当前 PR29 动态证据调整
P1NPU / TTS condition

Condition 全设备端融合

将 semantic projector 做成持久 session，并让 LLM hidden 通过后端中立的 device tensor 引用直接交给 TTS。

  • 预分配 projector graph、buffer 与 workspace，按常见 token 数做有界 shape cache。
  • 融合 emb_text gather、两层 MLP、L2 normalize、embedding add 与 audio BOS 写入。
  • 保留 CPU / 跨设备 fallback；scratch tensor 必须复制到有明确生命周期的持久 buffer。
RTF：直接消除 NPU→CPU→NPU正确性风险：低~中
P1NPU / Token2Wav

Token2Wav 全链路 device-resident

Token2Mel、flow state、mel、vocoder 输入与 cache 常驻 NPU，普通非 final 窗口只下载最终 PCM。

  • 复用固定 28-token / stride-25 图、常量、mask、timestep 与最大 workspace。
  • cache crop/copy 改为设备 ring buffer 或 view；layout conversion 走 D2D。
  • 最终 PCM 使用 pinned 双 buffer 异步 D2H，消费前才等待 event。
RTF：直接SPEAK→wav：直接先优化 non-final graph
P1CPU / steady state

去掉逐次分配、拷贝与线程创建

CPU 优化重点不是零散标量运算，而是高频分配、同步和整段内存整理。

  • LLM hidden 按 fragment 批量 D2H，复用双 buffer，去掉逐 token malloc/memcpy。
  • 复用 FFT plan、position tensor、batch vector；固定 shape 预计算 sin/cos。
  • Token/WAV cache 使用 ring buffer；PCM finite+clamp+F32→S16 用 SIMD，并交给单一有序 writer。
RTF：条件性CPU 占用：直接低风险先落地
P2NPU / small-M decode

为 M=1 单独设计 Transformer 路径

文本与语音自回归 decode 都是小 M；不要与 variable-M prefill 共用一套通用 matmul 策略。

  • 逐 shape 比较向量 GEMV 与 Cube GEMM；权重只预打包一次，先看 FFN gate/up 与 down projection。
  • 合并 gate+up、QKV 投影；融合 SiLU×mul、Q/K norm、RoPE 与 KV cache write。
  • 使用原生 GQA head 映射，禁止把 8 个 KV heads 物化扩展到 32 heads。
RTF：直接文本 + 语音共享按 end-to-end layer 选型
P2CPU↔NPU / TTS head

受控验证 TTS output head 上 NPU

768→6562 是最大显式 CPU 算术热点，但当前 32 线程实现已较快，历史 NPU 路线存在采样轨迹漂移，因此不能直接替换。

  • Stage A 只迁移 projection，CPU 保留 repetition penalty、top-k/top-p、RNG 与最终 sampling。
  • head_code、logits、workspace 全部持久化；不得逐 token 构图或申请。
  • 固定 seed 要求 speech token IDs 完全一致；通过后才尝试 device top-k，只回传 top-k values/IDs。
RTF：待 A/Btoken 轨迹硬门槛不通过则保留 CPU
P2VPM / APM / scheduler

只优化当前较慢的 Encoder

持续记录 Δencoder = TVPM − TAPM；谁更常为正就优先优化谁，接近持平后再交替推进。

  • VPM：相同尺寸 slice 有界 batch、输入/position buffer 复用、固定 shape session。
  • APM：1 秒音频块固定图、FFT/feature buffer 与 encoder workspace 常驻。
  • 若 std::async 有稳态成本，改为持久 worker；每 worker 独占 ACL context、stream、arena 与 completion event。
RTF：只取决于慢侧先分离 CPU/NPU 计时答案精度需复测
P2Overlap / latency

有界 LLM→TTS→Token2Wav 流水

在达到首个 28-token 窗口后立即触发非 final Token2Wav，用 double/triple buffer 降低 SPEAK→首段 PCM。

  • 队列必须有界，取消与 turn/epoch 校验必须能穿透所有 stage。
  • 优先尝试 CPU preprocess(i+1) || NPU encode(i)、PCM writer(i) || NPU window(i+1)。
  • T2M(i+1) || Vocoder(i) 只在独立 stream/event 且 CANN timeline 无明显争用时启用。
SPEAK→wav：主要目标RTF：不保证必须同时跑 isolated/overlapped
P3CANN backend

Plan cache 与 stream-scoped arena

减少 ACLNN GetWorkspaceSize、descriptor、常量和通用 workspace 的重复准备，但只缓存 API 文档允许跨调用复用的对象。

  • 按 op、dtype、shape、stride/layout、attribute、device 建有界 signature cache。
  • Qwen decode、TTS decode、每个 Token2Wav 图使用独立持久 arena。
  • 每 stream 独占 transient pool，以 event 建依赖，排查全局锁与隐式 device synchronize。
RTF：辅助收益降低 launch/allocator 开销先做 timeline

当前不建议做

不是永久禁止，而是在现有证据下不应作为第一轮主线
×
全局启用 ACL Graph

本分支曾出现同卡跨线程 capture 与同步 H2D 冲突。仅对固定 shape、固定地址、单 owner 的白名单图逐个启用。

×
全模型重做 weight layout

开发与回归面过大。只对 M=1 热 shape 的 gate/up、QKV、FFN 做内部预打包，并保留原始权重语义。

×
先量化 8B backbone

会同时改变精度、采样轨迹和基线口径；当前先消除重复同步与搬运。量化必须另开 baseline tag 单独评估。

×
恢复同卡粗粒度 TTS || T2W

历史 A/B 中两个 stage 都明显变慢，完整链路不足 1%。除非资源隔离与新 timeline 证明争用已经消失。

×
优化较快的 Encoder

VPM/APM 计时取 max；加速非临界侧没有 RTF 收益。以 Δencoder 分布而不是单个 kernel GFLOPS 决策。

×
以初始化或 final flush 为 RTF 主线

正式稳态会排除冷启动与最终 flush。它们可以改善体验，但优先级低于每 token / 每窗口重复工作。

×
物化展开 GQA 的 K/V

32 Q heads / 8 KV heads 应在 attention 内直接映射；四倍展开只会增加带宽和中间显存。

×
无界 shape cache 或流水队列

会把吞吐问题转化为内存、尾延迟和取消问题。只缓存常见 shape，并为每级队列设置容量和背压。

建议拆分为 6 个可回退 PR

每一步都先建立直接证据，再决定是否进入下一层融合或并发
PR 01Baseline / Observability

分离 CPU、NPU、sync、alloc、D2H/H2D 与 queue wait；记录 Δencoder。

PR 02Condition Device Fusion

持久 projector、device hidden handoff、L2/add/BOS 融合。

PR 03Token2Wav Residency

cache/mel/vocoder 常驻；普通窗口只下载 PCM。

PR 04Small-M Kernels

FFN、QKV、GQA-native decode；TTS head 仅受控实验。

PR 05CPU / Encoder

批量 hidden、预处理双缓冲、只优化临界 encoder。

PR 06Bounded Overlap

以 SPEAK→wav 为主目标；timeline 无争用后逐项启用。

统一验收

固定 seed token 轨迹；WAV SHA-256 或 Seed-TTS WER/SIM；至少 3 次预热 + 20 次测量；同时报告 pooled/stage RTF、SPEAK→首 WAV、P50/P95、同步/搬运次数和 CANN timeline。完整链路改善不足 1% 或质量退化即回退。
